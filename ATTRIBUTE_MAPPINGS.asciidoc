Every attribute of `sakila` which maps a column, grouped by its column type, its attribute type and its
converter: 116 attributes over the 16 tables and 7 views mapped (74 of tables, 42 of views). The column type is
`INFORMATION_SCHEMA.COLUMNS`', without the length; for the declared types, see
link:COLUMN_TYPES.asciidoc[Column Types]. Every table and view of `sakila` is mapped, and every column of each has
exactly one attribute but the 16 foreign-key columns of <<join-columns>>, which only an association maps.

No column is `JSON`, `VECTOR`, a spatial type other than `GEOMETRY`, or a `BINARY` / `VARBINARY`; no attribute
converts through a converter.

Each foreign-key column which has an attribute has one of its key's type.

`FilmCategory`, `Inventory` and `FilmText` map some foreign keys twice, as a basic attribute and as an
association over the same column, one of which only reads it. `inventory.film_id` and `store_id` are written by
the associations and only read by the attributes. `film_category.film_id` is written by the attribute `filmId`,
and `category_id` by the association `category`; both are `@Id`s of `FilmCategory`, whose `@IdClass`,
`FilmCategoryId`, maps no column. `film_text.film_id` is written by `FilmText`'s `@Id` and only read by its
`@OneToOne` to `Film`. `film_actor` maps its key in `FilmActorId`, which its associations name with
`@MapsId`.

[[large-objects]]
== Large objects

`staff.picture`, a `blob`, is the one `@Lob`: `@Lob @Basic(fetch = EAGER) byte[] picture` in `Staff`; a `blob`
holds 65,535 bytes at most, and `LAZY` on a basic attribute is a hint neither provider follows without bytecode
enhancement or weaving. A `text` column is a plain `String`, which Connector/J reads and writes whole.

[[spatial]]
== Spatial

`address.location` is a `GEOMETRY SRID 0` (with a `SPATIAL KEY`), and `Address.location` a `byte[]`, with no
converter: the bytes MySQL stores and returns, a four-byte little-endian `SRID` and the geometry's well-known binary
(WKB), which it also accepts back. `Address.newLocation(int, double, double)` builds the bytes of a point. Hibernate
Spatial is not used.

[[enums]]
== Enums

[cols="3,2,3,4",options="header"]
|===
| Column | Java type | Mapping | Note

| `film.rating`
| `Film.Rating`
| `@Enumerated(EnumType.STRING)`
| `enum('G','PG','PG-13','R','NC-17')`. `PG-13` and `NC-17` are not Java identifiers, so no constant can be named
after them. Each constant has a column value (`PG_13` is `PG-13`) in its `@EnumeratedValue` field, which the
provider writes and reads in place of the name. The specification infers `STRING` from the `String` field, without
`@Enumerated`; Hibernate ORM 7 does not and takes it as `ORDINAL`
(https://hibernate.atlassian.net/browse/HHH-20410[HHH-20410]), so the attribute says `@Enumerated(EnumType.STRING)`
for both providers.

| `film_list.rating`, `nicer_but_slower_film_list.rating`
| `Film.Rating`
| -
| The views' copies of `film.rating`. `FilmList` and `NicerButSlowerFilmList` are not entities, so no converter
applies; a row mapper or a `@ConstructorResult` hands the value over, and `Film.Rating.valueOfColumnValue(String)`
reads it.

| `film.special_features`
| `String`
| -
| `set('Trailers','Commentaries','Deleted Scenes','Behind the Scenes')`. A set holds any of its members, which
MySQL reads and writes joined by `,`. The attribute keeps the text; `Film.SpecialFeature.parse(String)` and
`format(Collection)` convert it from and to a set of `Film.SpecialFeature`s, whose column values are the members.

|===

Neither `Film.Rating` nor `Film.SpecialFeature` is an `AttributeEnum.OfString`, and `film.rating` takes no
`AttributeEnumConverter.OfString` of `jinahya-persistence-more`, as `oracle-sample-schemas-persistence`'s
`ShipmentStatus` and `postgresql-demodb-persistence`'s `FlightStatus` do; `@EnumeratedValue`, of Jakarta
Persistence 3.2, does its work.

[[converters]]
== Converters

No attribute converts through a converter, neither one of its own nor one of `jinahya-persistence-more`;
`Film.rating` is an `@Enumerated` with an `@EnumeratedValue`, see <<enums>>.
