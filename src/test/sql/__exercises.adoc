= Exercises
:toc: left
:toclevels: 3

The exercises on the installed `sakila` database: a section for each table and view, with a section for each
level, and, at the end, a section for the schema as a whole. Each exercise poses a problem; its answer, and
what the installed data gives back, are in the `.sql` file, and are checked by an integration test.

Run a file as a whole:

[source,sh]
----
docker exec -i mysql-sakila mysql -uroot -ppassword -t sakila < src/test/sql/<file>.sql
----

=== Intermediate

==== Exercise 1: the last names shared by more than three actors, the most shared first

Some last names are shared by several actors. Group the actors by
`last_name`, count them, and keep only the groups with more than three actors. Show each last name with its count,
the most shared name first; names with the same count are ordered by the name. The filter is on the groups, not on
the rows, so it belongs in `HAVING`, not in `WHERE`.

.`actor_exercises_02_intermediate.sql`, exercise 1
[%collapsible]
====
[source,sql]
----
SELECT last_name, COUNT(*) AS actors
FROM actor
GROUP BY last_name
HAVING COUNT(*) > 3
ORDER BY actors DESC, last_name
----

+-----------+--------+
| last_name | actors |
+-----------+--------+
| KILMER    |      5 |
| NOLTE     |      4 |
| TEMPLE    |      4 |
+-----------+--------+

link table. Show the five actors with the most films: their `actor_id`, `first_name`, `last_name` and the number of

=== Advanced

==== Exercise 1: the actors who appear in a film of every rating

Find the actors who have appeared in at least one film of each rating
(`G`, `PG`, `PG-13`, `R`, `NC-17`). This is a relational division: for each actor, count the distinct ratings of
their films, and compare that count with the number of distinct ratings over all films, taken by a subquery, so
the query does not hard-code the five ratings. Show the whole rows of the first five such
actors by `actor_id`.

.`actor_exercises_03_advanced.sql`, exercise 1
[%collapsible]
====
[source,sql]
----
SELECT a.*
FROM actor a
         JOIN film_actor fa ON fa.actor_id = a.actor_id
         JOIN film f ON f.film_id = fa.film_id
GROUP BY a.actor_id, a.first_name, a.last_name
HAVING COUNT(DISTINCT f.rating) = (SELECT COUNT(DISTINCT rating) FROM film)
ORDER BY a.actor_id
LIMIT 5
----

==== Exercise 1: the addresses no customer, staff member or store has

An address is referred to by a customer, a staff member or a store. Find
the addresses which none of the three refers to, the whole rows, by `address_id`.
Three `NOT EXISTS` conditions, each a correlated subquery on a different table. The installed data has none.

.`address_exercises_03_advanced.sql`, exercise 1
[%collapsible]
====
[source,sql]
----
SELECT a.*
FROM address a
WHERE NOT EXISTS (SELECT 1 FROM customer c WHERE c.address_id = a.address_id)
  AND NOT EXISTS (SELECT 1 FROM staff s WHERE s.address_id = a.address_id)
  AND NOT EXISTS (SELECT 1 FROM store s WHERE s.address_id = a.address_id)
ORDER BY a.address_id
----

....
no rows.
....
