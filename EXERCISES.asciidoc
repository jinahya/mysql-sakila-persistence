= Exercises
:toc: left
:toclevels: 3

The exercises on the installed `sakila` database: a section for each table and view, with a section for each level, and, at the end, a section for the schema as a whole.
Each exercise poses a problem; its answer, and what the installed data gives back, are in the `.sql` file, and are checked by an integration test.

Run a file as a whole:

[source,sh]
----
docker exec -i mysql-sakila mysql -uroot -ppassword -t sakila < src/test/sql/<file>.sql
----

       a.last_name,

         JOIN film f ON f.film_id = fa.film_id

GROUP BY a.actor_id, a.first_name, a.last_name

==== SAKILA-ACTOR-A-02: the actors in the top seven film counts, ties included

Rank the actors by the number of films they appear in, so that actors with the same number share a rank and the next number takes the next rank.
Show the actors of the first seven ranks: `actor_id`, `first_name`, `last_name`, the number of films and the rank, ordered by the rank and then by `actor_id`.
Unlike the `LIMIT` of SAKILA-ACTOR-I-02, `DENSE_RANK()` keeps every actor tied at the last rank.

.`actor_exercises_03_advanced.sql`, SAKILA-ACTOR-A-02
[%collapsible]
====
[source,sql]
----
SELECT actor_id, first_name, last_name, films, film_rank
FROM (SELECT a.actor_id,
             a.first_name,
             a.last_name,
             COUNT(*)                                   AS films,
             DENSE_RANK() OVER (ORDER BY COUNT(*) DESC) AS film_rank
      FROM actor a
               JOIN film_actor fa ON fa.actor_id = a.actor_id
      GROUP BY a.actor_id, a.first_name, a.last_name) ranked
WHERE film_rank <= 7
ORDER BY film_rank, actor_id
----

==== SAKILA-ACTOR-A-03: the longest film of each of the first five actors

For each of the actors `1` to `5`, find the longest film they appear in.
Show the `actor_id`, the `first_name`, the `last_name`, the film's `title` and its `length`, ordered by `actor_id`; if two films of an actor share the longest length, both are shown, ordered by `title`.
A correlated subquery takes the longest length of the actor of the outer row.

.`actor_exercises_03_advanced.sql`, SAKILA-ACTOR-A-03
[%collapsible]
====
[source,sql]
----
SELECT a.actor_id, a.first_name, a.last_name, f.title, f.length
FROM actor a
         JOIN film_actor fa ON fa.actor_id = a.actor_id
         JOIN film f ON f.film_id = fa.film_id
WHERE a.actor_id BETWEEN 1 AND 5
  AND f.length = (SELECT MAX(f2.length)
                  FROM film_actor fa2
                           JOIN film f2 ON f2.film_id = fa2.film_id
                  WHERE fa2.actor_id = a.actor_id)
ORDER BY a.actor_id, f.title
----

==== SAKILA-SCHEMA-A-06: how many actors are one film, and how many two films, away from KEVIN BLOOM; a Bacon number, Sakila having no KEVIN BACON

Two actors are one film apart when they appear in the same film; two films apart when they are one film apart from someone who is one film apart from the first.
Starting from `KEVIN BLOOM`, walk `film_actor` with a recursive common table expression, up to two steps, keep each actor's smallest number of steps, and count the actors at one and at two.
Sakila has no `KEVIN BACON`, so this is the Bacon number of KEVIN BLOOM.

.`_schema_exercises_03_advanced.sql`, SAKILA-SCHEMA-A-06
[%collapsible]
====
[source,sql]
----
WITH RECURSIVE bacon (actor_id, number) AS (
    SELECT actor_id, 0 FROM actor WHERE first_name = 'KEVIN' AND last_name = 'BLOOM'
    UNION DISTINCT
    SELECT fa2.actor_id, b.number + 1
    FROM bacon b
             JOIN film_actor fa1 ON fa1.actor_id = b.actor_id
             JOIN film_actor fa2 ON fa2.film_id = fa1.film_id
    WHERE b.number < 2)
SELECT number, COUNT(*) AS actors
FROM (SELECT actor_id, MIN(number) AS number FROM bacon GROUP BY actor_id) t
WHERE number > 0
GROUP BY number
ORDER BY number

==== SAKILA-SCHEMA-A-08: the five longest runs of days on which a customer rented every day

A run is a series of consecutive days on each of which the customer rented at least once.
Take each customer's distinct rental days, and subtract from each day its number among the customer's days, with `ROW_NUMBER()`; the days of one run all give the same date, so group by it.
Show the five longest runs: the customer's `customer_id`, `first_name` and `last_name`, the run's first and last day and its number of days, the longest first; ties are ordered by `customer_id` and then by the first day.
This is the gaps-and-islands technique.

.`_schema_exercises_03_advanced.sql`, SAKILA-SCHEMA-A-08
[%collapsible]
====
[source,sql]
----
WITH days AS (SELECT DISTINCT customer_id, DATE(rental_date) AS day
              FROM rental),
     islands AS (SELECT customer_id, day,
                        DATE_SUB(day, INTERVAL ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY day) DAY) AS island
                 FROM days)
SELECT c.customer_id, c.first_name, c.last_name, MIN(i.day) AS first_day, MAX(i.day) AS last_day, COUNT(*) AS days
FROM islands i
         JOIN customer c ON c.customer_id = i.customer_id
GROUP BY c.customer_id, c.first_name, c.last_name, i.island
ORDER BY days DESC, c.customer_id, first_day
LIMIT 5

.`_schema_exercises_03_advanced.sql`, SAKILA-SCHEMA-A-09
[%collapsible]

[source,sql]
----
SELECT co.country, COUNT(*) AS customers
FROM country co
         JOIN city ci ON ci.country_id = co.country_id
         JOIN address a ON a.city_id = ci.city_id
         JOIN customer cu ON cu.address_id = a.address_id
WHERE NOT EXISTS (SELECT 1
                  FROM customer cu2
                           JOIN address a2 ON a2.address_id = cu2.address_id
                           JOIN city ci2 ON ci2.city_id = a2.city_id
                           JOIN rental r ON r.customer_id = cu2.customer_id
                           JOIN inventory i ON i.inventory_id = r.inventory_id
                           JOIN film_category fc ON fc.film_id = i.film_id
                           JOIN category c ON c.category_id = fc.category_id
                  WHERE ci2.country_id = co.country_id
