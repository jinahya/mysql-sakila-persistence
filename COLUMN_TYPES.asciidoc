Every column type the tables of `sakila` declare, grouped by the sections of link:{data-types}[Data Types] in the
MySQL 9.7 Reference Manual. Each type is listed as the catalog (`INFORMATION_SCHEMA.COLUMNS`) reports it, and each
column as `table.column`; 90 columns of 16 tables in all. The views are left out; see <<views>>.

The Java type is the type of the attribute which maps the column in the entity classes, the wrapper types, never a
primitive, and `java.time` for the date and time types. Sixteen foreign-key columns have no attribute of their own,
only an association's `@JoinColumn` (see link:ATTRIBUTE_MAPPINGS.asciidoc[Attribute Mappings]); each is listed with
the type of the key it refers to, an `Integer` in every case.

No column is `BIGINT`, `BIT`, `FLOAT`, `DOUBLE`, `DATE`, `TIME`, `BINARY`, `VARBINARY`, `TINYTEXT`, `MEDIUMTEXT`, `LONGTEXT`,
`TINYBLOB`, `MEDIUMBLOB`, `LONGBLOB`, `VECTOR`, a spatial type other than `GEOMETRY` (`POINT`, `POLYGON`, ...) or
`JSON`.

== Numeric Data Types

See link:{refman}/numeric-types.html[Numeric Data Types].

=== Integer Types

See link:{refman}/integer-types.html[Integer Types (Exact Value) - INTEGER, INT, SMALLINT, TINYINT, MEDIUMINT, BIGINT].

Every integer is an `Integer`. The tables declare their integers
`UNSIGNED`: a `tinyint unsigned` (up to 255) exceeds a `Byte`, and a `smallint unsigned` (up to 65535) a `Short`, so
`Integer` is the smallest wrapper which holds every value of each, and of a `mediumint unsigned` (up to 16777215).
`payment.rental_id` and `rental.rental_id`, `int`s, are the only signed ones.

`tinyint(1)` is what the catalog reports for `BOOLEAN`, a synonym (see
link:{refman}/numeric-type-syntax.html[Numeric Data Type Syntax]); `customer.active` and `staff.active` are declared
`BOOLEAN NOT NULL DEFAULT TRUE`. Connector/J reads it as a `Boolean`
(`tinyInt1isBit`, `true` by default).

A foreign-key column has its key's type in every case: the keys and the columns which refer to them are declared
alike.

=== The DATE, DATETIME, and TIMESTAMP Types

See link:{refman}/datetime.html[The DATE, DATETIME, and TIMESTAMP Types].

`datetime` and `timestamp` hold a date and a time to the second, and are `LocalDateTime`s. MySQL converts a
`timestamp` from the session time zone to UTC for storage and back on read, and a `datetime` not at all. Every
`last_update` is a `timestamp DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`, which the database sets on
each insert and update.

[[views]]
== Views

A view's columns take the types of the expressions which select them, so the views add no type outside the
sections above:

* `actor_info.film_info`, `film_list.actors` and `nicer_but_slower_film_list.actors` are `GROUP_CONCAT`s, `text`.
* `customer_list.name`, `staff_list.name` and `sales_by_store.manager` (`varchar(91)`) and `sales_by_store.store`
  (`varchar(101)`) are `CONCAT`s of `varchar` columns; `customer_list.notes`, an `IF` of two literals, is a
  `varchar(6)`.
* `sales_by_film_category.total_sales` and `sales_by_store.total_sales` are `SUM`s of `payment.amount`, a
  `decimal(27,2)`.
* Every other view column is a table column, and has its type.
